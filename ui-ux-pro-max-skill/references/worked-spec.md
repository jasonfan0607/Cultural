# 实例：把本项目的修复请求写成可验收规格

这是一份根据既有修复反向整理的规格示例，用于展示表达方式，不是新增开发任务。下面的“已有覆盖”指脚本目前包含该验证，不代表本次文档编辑重新执行了测试。

## 案例 A：AI 回复空白，历史记录点了没反应

### 原话与意图

原话：“这个页面现在怎么用不了”“点击以前的记录，没有反应，和刚才的问题一并修复”。

意图：文化设计使用者提交完整描述后，能够知道生成是否进行中、取得结果或明确失败原因；在同一浏览器与同一来源地址下，能重新打开之前的对话继续使用。

范围：生成反馈、历史保存加载、刷新恢复和切换竞态。不包含跨账户同步、文本模型接入、数据库结构修复或真正的作品收藏。真实服务响应时间由外部服务决定，不承诺固定时间出图。

### 需求分解

| 需求 | 输入及状态 | 可观察输出 | 数据和模块约束 |
|---|---|---|---|
| A-REQ-01 生成反馈 | 描述 → 文字 → 生图等待 → 成功或失败 | 文字方案、可见进度、图片或错误 | `generateReply`；完整描述与用途传给图片服务 |
| A-REQ-02 历史恢复 | 有内容的对话 → 保存 → 新建或刷新 → 点击历史 | 正确消息顺序和图片地址恢复 | 稳定会话 ID；同来源 localStorage；延用当前 50 条上限 |
| A-REQ-03 异步隔离 | A 等待中 → 切换 B → A 迟到 | B 内容不被 A 修改 | 取消等待并检查请求身份；页面卸载同样处理 |
| A-REQ-04 可恢复失败 | 网络、无权限、无效响应、超时、图片过期 | 具体提示与重试操作；已生成文字保留 | 延用默认 120 秒超时；不把失败回复标成成功图片 |

### 状态契约

`idle → generating → success | error | cancelled`；`error/cancelled → generating` 为重试。

文字与图片分阶段更新。切换会话后，原请求的任何回调不能再修改当前对话；从存储加载的未完成请求应成为“已中断、可重试”，不能一直显示等待。

### 验收集

| AC / 需求 | 前置与操作 | 判定标准 | 覆盖位置或验证方式 |
|---|---|---|---|
| A-01 / 01 | 延迟生图响应，发送“昆曲主题的现代简约白色文化衫” | 在图片返回前，文字和“正在生成”可见；请求包含白色、文化衫和完整描述 | `ai-design.browser.cjs` 验证阶段显示；`volcengine.test.js` 验证描述传递 |
| A-02 / 01 | 服务返回合法图片地址 | 页面显示对应图片；完成解码后截图确认内容，不只数 img 标签 | 浏览器 Mock 已覆盖显示；真实图片需单独联网检查 |
| A-03 / 02 | 成功对话后新建，再点击历史；同来源刷新后再点 | 恢复同一对话内容，新增消息更新原记录而不创建重复会话 | `ai-design.browser.cjs` |
| A-04 / 03 | A 请求挂起，新建 B 并完成，再释放 A 响应 | B 仍只包含 B 的消息；A 显示已取消；无空 DOM 引用错误 | `ai-design.browser.cjs` |
| A-05 / 04 | 分别注入 401、错误 JSON、空图片数组和网络错误 | 结束等待并给出可理解的错误，不出现无限空白回复 | `volcengine.test.js`；401 重试由浏览器脚本覆盖 |
| A-06 / 04 | 注入永不完成的请求 | 达到配置上限后终止等待并可重试；测试可缩短计时，不实际等两分钟 | `volcengine.test.js` |
| A-07 / 02、04 | 保存后阻断图片资源，再打开历史 | 文本仍在，显示图片失效反馈和重试入口 | 补充专项场景；当前不能声称已有自动覆盖 |
| A-08 / 02 | 模拟存储满或不可写，再生成对话 | 明确提示当前内容不能持久保存；不能声称刷新后可恢复 | 补充专项场景；当前不能声称已有自动覆盖 |

### 实现依赖

先定义请求完成与取消的边界，再实现两阶段反馈；随后接入真实历史快照，最后补足切换、刷新和失败恢复验证。只替换气泡样式无法满足 A-REQ-02～04。

## 案例 B：我的收藏没有图片

### 意图与范围

意图：打开个人中心时，当前三条文化主题卡片应显示与标题一致的封面，即使外部随机图片服务不可达也不受影响；封面资源本身缺失时应有明确替代显示。

事实：页面三条数据是前端示例。此次修复目标是封面展示，不是实现真实收藏。不能把“卡片有图”验收成“用户收藏流程完成”。

| 需求 | AC | 条件与操作 | 可观察判定 |
|---|---|---|---|
| B-REQ-01 本地主题封面 | B-01 | 阻断所有非本地请求，打开个人中心 | 三张封面全部解码成功，分别对应云锦、刺绣和紫砂壶 |
| B-REQ-02 失败反馈 | B-02 | 阻断其中一张本地图 | 该卡片显示标题与“封面暂不可用”；其他图片正常，不重复请求死循环 |
| B-REQ-03 响应式与可识别性 | B-03 | 桌面与 390×844 视口刷新、滚动 | 图片可见且主题可辨；标题、数量、卡片点击入口保留；无横向裁切造成操作丢失 |
| B-REQ-04 内容真实性 | B-04 | 检查图片原件和来源说明 | AI 主题示意图保留来源及标记，不称为真实藏品照片 |

`profile-collections.browser.cjs` 覆盖 B-01、B-02 以及 B-03 的图片加载部分。主题匹配、完整布局和 B-04 需要人工视觉/来源检查，不把移动视口加载测试夸大为完整移动端适配证明。

## 若需求升级为“真实收藏”

重新定义需求：登录用户点击收藏后，必须保存目标 ID、目标类型和用户归属；个人中心读取真实记录；取消收藏、重复点击、未登录及刷新都有明确结果。需要校验后端鉴权和数据库契约。

这组新需求不能用当前三条示例数据或 AI 页的成功提示满足。先写新的验收集，再按授权实施，不在封面修复中悄悄扩展范围。
