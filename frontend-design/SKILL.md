# Frontend Design：Cultural 项目经验版

本技能将已有 frontend-design 的视觉质量关注点扩展为“有文化辨识度、真实可操作、有证据可验收”的项目方法。它是项目内独立版本，不宣称已覆盖个人全局技能。

## 入口与产出

有规格时按需求 ID 实现；没有规格时，先写出本次用户意图、范围和可观察验收条件。复杂需求可使用项目内 `ui-ux-pro-max-skill`；该技能不可用时仍应完成必要的简短规格，不将它变成强制依赖。

按任务读取 [项目界面约束](references/cultural-ui.md) 和 [界面评测集](references/frontend-evals.md)。目标产出是实现、相关验证证据与真实限制，而不是只有漂亮截图。

## 1. 延续项目视觉，再决定是否重设计

- 修复现有页面时，沿用页面结构、文化语义和主要操作，不借小修复重做全站。
- 需要新设计时，先说明服务人群、关键任务和视觉方向。Cultural 可从云锦织纹、苏绣细节、紫砂器形、江南留白中选择与内容相关的线索。
- 颜色、字体和装饰服务阅读与行动。项目已有紫红、暖白、金色可作为默认延续；它们不是所有未来页面的强制答案。
- 字体优先保证中文可读与本地回退；不要为了“独特”让标题断词、正文过细或外部字体加载阻塞使用。
- 图片与内容对应。AI 主题示意图、真实文物照片和用户生成作品要保持语义区别，不能把无关素材当作修复结果。

## 2. 让视觉变量和布局真正生效

- Vue `scoped` 样式中的 `:root` 可能被编译成带作用域的根选择器，无法命中 HTML 根元素。组件变量放在实际页面根类；真正的全局变量使用全局样式。
- 不只检查 CSS 是否有定义，还检查浏览器计算后的颜色、尺寸、透明度与层级。加载点曾因未定义变量变成透明，必须能实际看见。
- 固定导航与页面内容之间有明确空间；高层级玻璃背景不能遮住标题和可点击控件。
- 宽屏、窄屏和内容增多都需要可用。检查文本截断、图片比例、长消息滚动、输入区可达性以及历史入口；隐藏侧栏前要确认里面的重要操作仍有入口。
- 风格修复应在本页面范围内实施，避免全局选择器影响其他模块。

## 3. 交互按状态设计

对本次涉及的操作列出默认、等待、成功、空与失败状态；涉及生成、上传或请求时再补取消、重试及中断恢复。

- 等待状态既要有可见反馈，也要给出准确含义；不要让用户盯着空白气泡。
- 可分阶段展示的结果及时展示。Cultural 中本地文字方案不必等待远端图片完成。
- 请求有超时和错误分类，失败后保留用户输入或已有结果；适度提供重试，不无限自动重发昂贵请求。
- 新建、切换和离开页面时处理正在进行的工作；请求结果用稳定身份绑定，不依赖会变化的列表索引。
- 清理定时器、监听和请求；DOM 更新后重新确认引用是否存在。取消客户端等待不要表述成保证取消服务端计算。
- Enter 发送、Shift+Enter 换行与中文输入法组合输入互不冲突；可点击非按钮元素需要相应的键盘语义。

## 4. 数据真实性属于界面质量

成功提示只能跟随已完成的行为。实现“收藏”时查是否真的保存和查询；实现“历史”时查是否真的恢复消息；不要用静态卡片制造用户数据已经存在的错觉。

同来源 localStorage 适合本机历史，但不等于账户隔离或跨设备同步。需求涉及后两者时先补数据契约。读取历史遇到损坏或未完成状态时应给出可恢复行为；存储失败不能提示“已永久保存”。

对于现有示例页面中的局部图片修复，可以保留示例范围，但交付说明不得声称真实业务闭环已经实现。

## 5. 图片必须能加载，也必须有意义

- 优先使用项目中可验证、与主题对应的素材。当前收藏示例使用同站本地封面，避免依赖随机图服务。
- 只有在允许保存与再分发的素材范围内才做本地副本；保留已有来源说明和标记。不把登录受限图片或短期签名链接当永久公共资源。
- 失败或空地址有清楚的替代内容、标题和适当 alt；不能反复把同一个失效 URL 设回 src 形成死循环。
- 校验 HTTP 与实际图像解码，并目视检查裁切后的主体。不能用网络 200、DOM 中有 img 或尺寸非零单独证明封面正确。
- 真实用户作品保留其原图含义；失效时解释和提供恢复操作，不静默换成一张“看起来不错”的示例图。

## 6. 选择足够的验证

按风险选择测试，不要求每次改字都补测试。已有同类回归优先复用：

- `tests/volcengine.test.js`：请求内容、接口错误、超时、取消。
- `tests/ai-design.browser.cjs`：阶段反馈、历史恢复、重试和迟到响应。
- `tests/profile-collections.browser.cjs`：同站封面、窄屏加载、缺图替代。

浏览器脚本位于前端目录；依赖与运行条件见项目根 README。测试工具路径按当前环境发现，不写死开发者机器路径。

验证分层：逻辑测试 → 必要的浏览器交互 → 图片/布局视觉检查 → 构建。只运行与改动有关的层级；真实第三方调用按任务需要验证，Mock 不能替代真实联通性证据。

## 7. 按实际结果交付

报告用户操作前后的变化、已通过的验收和仍存在的边界。页面里没有真实实现的按钮不称为完成；测试没有覆盖的状态不称为全部通过。用户要求提交时，再检查差异、排除本地配置并核对远程提交。
