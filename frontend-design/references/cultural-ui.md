# Cultural 界面约束与经验来源

依据 2026-11-14 项目源码整理，使用前检查相关代码是否已有变化。路径相对项目根目录。

## 技术与页面入口

- Vue 3 Composition API、Vue Router、Vite；主页面位于 `ai-culture-design/src/views`。
- 全局导航与路由过渡位于 `src/App.vue`（前端目录内），修复遮挡时同时检查页面内边距和导航位置。
- Element Plus 与其他已有组件样式共存，新增 UI 先检查已有组件行为和 reset 样式，不为了一个按钮再引入一套组件库。
- `AiDesignView.vue` 的历史、`ProfileView.vue` 的收藏、`volcengine.js` 的生成请求是不同职责，不应把 UI 卡片数组当接口契约。

## 可沿用的视觉方向

| 目的 | 项目中的可用语言 | 验证方式 |
|---|---|---|
| 文化辨识度 | 云锦纹理、苏绣针线、紫砂器形；暖白背景与紫红重点色 | 素材主题与标题匹配，不用随机风景替代文化内容 |
| 阅读层级 | 主要标题、说明、内容区、操作区 | 不看装饰也能找到主要动作；正文在实际背景上清楚 |
| 图片展示 | 当前收藏封面采用固定容器与 cover 裁切 | 在桌面和窄屏检查完整主体，原图来源和标记不被擅自修改 |
| 反馈 | 文字状态配合有限动效 | 关掉动效或网络变慢后仍能理解当前状态 |
| 复用 | 页面局部变量、已有圆角与间距、已有图标体系 | 改动不使相邻页面视觉和行为发生意外变化 |

已有 `#8b1538`、`#c9a962` 等色值是延续设计的参考，不是品牌规范已经正式确定的证据。对比度、字号和触控尺寸根据实际背景、目标设备及本次规格验证。

## 四个可以复用的工程决策

### CSS 变量落到真实元素

原 AI 页在 scoped 样式里声明 `:root`，加载点还引用了未定义变量，导致状态不可见。可将变量定义在 `.ai-design-page` 等实际根元素；用浏览器的 computed style 检查最终颜色。

此规律适用于相同编译行为，不意味着项目里每个 `:root` 都已经修好。`ProfileView.vue` 中仍有 scoped `:root`，本次收藏图片修复没有宣称完成全站主题治理。

### 把请求归属和界面归属对应起来

使用稳定会话 ID 和当前请求身份；切换前结束等待，写回前确认请求仍属于当前工作。单纯删除加载组件不能阻止迟到响应修改状态。

`nextTick` 后检查当前 DOM 引用，避免定时器捕获的旧引用。需要计时器时明确清理位置，而不是靠延时“应该已经渲染”。

### 将图片服务故障降级为局部可理解状态

`ProfileView.vue` 的三条示例收藏现使用 `public/images/collections` 中的本地图。失效时显示项目名称和缺图提示；其他卡片继续正常使用。

这些图是 AI 主题示意图，来源见同目录 README。不能把该经验解释为任何图都可以复制到仓库，也不能用示例图覆盖真实用户作品。

### 明确持久化的边界

AI 页现有历史是当前来源下的浏览器记录；`localhost:5175` 与 `127.0.0.1:5175` 是不同来源。恢复的是对话和图片地址，图片服务链接仍可能过期。

目前 AI 页收藏按钮只是提示；个人中心收藏与作品仍有示例数据。实现真实收藏时必须另行定义数据写入、查询和用户归属，不能仅复用视觉组件后宣称完工。

## 现状不是验收目标的上限

AI 页窄屏样式当前会隐藏历史区，这不是“移动端历史恢复已完善”的证据。如果新需求包含手机操作历史，应该设计可访问的替代入口并验收。未涉及该需求的小修复只记录限制，不自动扩大范围。

直接请求生图服务仍会让前端配置进入浏览器。公开生产部署应按需要改为后端鉴权；仅将硬编码值移动到 `.env.local` 不能称为密钥已在服务端保护。
