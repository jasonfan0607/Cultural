# 界面实现与技能行为评测

两类评测分开记录：产品是否满足规格，以及执行者是否正确运用了技能。以下是可选择的场景，不是每次 UI 改动必须全跑的清单。

## 产品评测场景

| 编号 | 条件与操作 | 通过判据 | 自动化与人工分工 |
|---|---|---|---|
| UI-01 等待可见 | 生图请求保持 pending，发送完整文化设计描述 | 文本与加载状态可见，发送不会产生重复活动请求，取消入口可用 | 浏览器断言状态；目视检查计算颜色与遮挡 |
| UI-02 迟到响应 | A 尚未完成时切换 B，再让 A 返回 | B 不出现 A 的内容，状态不被旧 finally 回调重置，无空引用异常 | 路由拦截控制响应顺序；检查最终消息与 pageerror |
| UI-03 历史恢复 | 生成后新建、点击历史、同来源刷新再点击 | 文字和图片地址对应原会话；图片解码后可见 | 验证消息与记录，再做截图检查；不把 Mock 图当真实生图证据 |
| UI-04 资源失败 | 屏蔽外部图片，再阻断一张本地图 | 本地收藏封面正常；单图失败有标签占位；不循环重试 | 使用现有收藏浏览器脚本，人工核对主题与裁切 |
| UI-05 输入法 | 中文组合输入时按 Enter，随后正常 Enter；Shift+Enter | 组合输入不误发送，正常 Enter 发送一次，Shift+Enter 换行一次 | 真实输入法适合人工验证；合成键盘事件不能证明所有输入法正常 |
| UI-06 窄屏与长内容 | 桌面和 390×844 显示长标题、多条消息及图片 | 主要操作可达，文字和图不造成不可操作溢出；规格要求的历史入口仍可用 | 图片加载脚本只覆盖部分；必须补布局和操作检查 |
| UI-07 真实收藏 | 登录用户收藏后刷新个人中心，再取消收藏 | 列表与实际持久化一致，数量准确，其他用户不可读取 | 这是后续业务需求的评测；当前示例卡片和成功提示不满足 |
| UI-08 生产图片资源 | 构建后通过静态预览访问收藏页 | 本地封面资源被产物包含且加载成功 | build 仅证明构建；需要部署/预览路径与网络检查 |

## 技能行为测试输入

1. “只修收藏封面，不改变页面样式。”
   - 应选择有依据的主题素材、局部失败态和相关验证。
   - 不应重写导航、编造用户收藏或接入新的账户系统。
2. “AI 页面做得高级一点，发送以后一直没反应。”
   - 应先确认无反馈的功能问题，再在已有视觉方向内改进状态显示。
   - 不应只加动画和渐变，或让装饰遮住结果。
3. “移动端也要能打开历史。”
   - 应识别隐藏侧栏造成入口缺失，提供可访问入口并验证恢复行为。
   - 不应以“手机截图没有横向滚动”代替功能验收。
4. “设计一个新的文化活动页面。”
   - 应从活动内容、参加流程与用户任务选择视觉方案，保留项目必要一致性。
   - 不应强制复制 AI 对话页布局、120 秒等待或全部历史规则。
5. “截图里有三条收藏，接上真实接口就行。”
   - 应检查接口、数据字段、身份与失败状态，说明示例与真实列表的差别。
   - 不应只把静态数组重命名为 API 数据，或把登录标志夹具当鉴权验证。

## 评审与记录

每个实际执行的场景记录输入、代码版本、环境、预期、实际结果、截图/测试输出位置及覆盖限制。

通过条件：本次规格内的用户行为、数据语义和视觉可用性均有证据；失败路径不会伪报成功。关键失败包括：串会话、伪造保存、图片仍空白、核心操作被遮挡，以及把未运行测试报告为通过。

截图要在过渡动画结束和图片解码后获取。至少观察内容与主题是否一致、固定导航是否遮挡、操作是否可达；这些结论不能由像素尺寸断言单独得出。

未执行的案例写“未执行”。已有构建警告与实际功能失败分别报告，不把无关旧警告当本次新回归，也不因构建通过而忽略视觉缺陷。
